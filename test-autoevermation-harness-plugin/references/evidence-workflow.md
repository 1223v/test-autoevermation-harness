# 테스트 생성을 위한 근거 중심 작업

Superpowers의 조사·작은 실행 단위·원인 분석·완료 전 검증 원칙을 하네스 목적에 맞게 내장한다. 별도 Superpowers 설치나 스킬 호출은 필요 없다. 기존 파이프라인 단계, 승인과 종료 조건을 재사용한다.

1. **구조와 관련 파일 읽기**: 프로젝트 루트, 모듈, 빌드 파일, 소스·기존 테스트·스펙, 대상 심볼과 호출 경로를 확인한다. 읽지 않은 코드의 동작을 가정하지 않는다. 분석 범위와 미확인 부분을 기록한다.
2. **실제 버전의 공식 문서 확인**: `detect_spring_profile`·빌드 파일·잠금/해결 결과에서 Java/Spring/JUnit/Mockito/JaCoCo 버전을 확인한다. 사용할 API·애노테이션·빌드 옵션을 해당 버전 공식 문서로 확인한다. 최신 문서를 구버전에 그대로 적용하지 않는다. 버전 충돌은 질문/보류한다. 웹 접근 불가 시 미확인 내용을 표시하고 필요한 의미가 확인될 때까지 의존 작업을 보류한다.
3. **근거 있는 TODO**: 기존 단계 산출물의 `evidence` 또는 `_workspace/research.md`에 `파일·심볼 | 공식 URL | 확인 버전 | 적용 결정`을 남기고 필요한 작업만 나열한다. 작업마다 입력, 기대 산출물, 필요한 검증을 연결한다. 별도 계획 승인 게이트는 추가하지 않는다.
4. **실행**: 승인된 시나리오를 구현하고 원래의 JUnit·JaCoCo·적합성 절차를 수행한다. 독립된 분석 외에는 의존 순서를 지킨다. 기존 역할·스키마를 재사용한다.
5. **실패 원인과 결과 확인**: 로그·JUnit·컴파일 진단·미커버 분기·시나리오 target 호출에서 원인을 확인하고 가장 작은 수정만 한다. 수정 이후 영향받는 테스트와 보고서를 새로 실행·확인한다. 실행 명령, 대상, 시각, 결과 경로와 남은 문제를 기록한다. 실행하지 못한 환경을 통과로 보고하지 않는다.

파일·빌드 버전·대상·질문 결정이 바뀌지 않았다면 조사 결과와 공식 URL을 재사용한다. 소스나 빌드가 바뀌면 관련 근거만 갱신한다. **조사 재사용과 실행 증거 재사용은 다르다**: 재개 시 낡은 JUnit·JaCoCo·적합성 결과를 성공 근거로 사용하지 않는다.

이 하네스는 테스트를 생성하기 위한 도구다. 생성 테스트를 검증하는 별도 테스트, 의무 RED–GREEN TDD, mutation testing, 메타 테스트, 중복 리뷰/승인을 추가하지 않는다. 실제 테스트 실행·보정·커버리지·시나리오 검증은 생략하지 않는다. 기존 반복 종료 조건과 사용자 승인 범위를 지킨다.

근거: [Superpowers 기본 작업 흐름](https://github.com/obra/superpowers#the-basic-workflow), [공식 스킬 작성 지침](https://developers.openai.com/plugins/build/skills). 버전별 Spring/JUnit 등의 근거는 해당 대상 프로젝트를 조사할 때 추가한다.
